Injection Labs Demo

Educational only. This app is intentionally vulnerable to SQL injection plus command injection in dedicated labs. Do not expose it to the internet.
Verbose error responses
On: server returns the full Postgres error JSON (error, detail, position, executedSql). Off: server returns only a generic 500 with a short ERROR: <message> string.

SQL Injection Track

Endpoint POST /api/records. Returns only the last result set from pool.query, so injection has to leak data through Postgres error messages (cast errors, etc.).
Endpoint POST /api/lab2/records. Same vulnerable INSERT, but the server splits the SQL on ; and runs each statement separately. Errors from the original INSERT are collapsed to a generic syntax error / unterminated quoted string — error-based payloads inside the INSERT body do not leak. Errors from stacked statements (anything after a ;) are returned verbatim, so a payload like '); SELECT CAST(version() AS int) -- leaks the cast value through the error message. Successful stacked SELECTs still appear in resultSets.
Endpoint POST /api/lab3/records. Same as Lab 2 (statement split, sanitized INSERT errors, verbose stacked-statement errors), but every literal space character is stripped from each field before concatenation. ' OR 1=1 -- collapses to 'OR1=1-- and breaks. Use non-space whitespace tokens instead: \t / \n / /**/. The response echoes back a filteredValues object so you can confirm what actually reached the SQL.
Endpoint POST /api/lab4/records. Same as Lab 3, plus a case-insensitive SELECT and UNION denylist: both substrings are stripped from each field before concatenation. The classic SELECT … FROM and UNION SELECT patterns die. Bypass with PostgreSQL features that don't need those keywords:
  • TABLE foo — shorthand for SELECT * FROM foo.
  • VALUES (expr, …) — top-level expression rows.

Command Injection Track

Endpoint POST /api/cmdi/lab1/ping. The backend builds and runs ping -c 1 <target> with child_process.exec. It strips only literal spaces from target before interpolation. Shell metacharacters and non-space whitespace can still be abused for command injection in this intentionally vulnerable lab.
